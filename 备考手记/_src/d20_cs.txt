# 一、网络层到底干什么
:::def 路由 vs 转发
路由：全局，算出路径，生成路由表。转发：本地，查表把分组送到输出端口。一个后台算，一个一直在做。
:::
数据报和虚电路：
| 维度 | 数据报 | 虚电路 |
| 连接 | 无连接 | 先建立 |
| 路径 | 每个分组独立选路 | 同一路径 |
| 顺序 | 可能乱序 | 按序 |
| 路由器 | 不记连接 | 记虚电路 |
| 故障 | 影响小 | 该路径的虚电路全断 |

Internet 网络层是==无连接、不可靠==的数据报服务。虚电路也不等于可靠，它只保证按序走同一条路。

拥塞是全局的（路由器队列爆满丢包），流量控制是端到端的（接收方跟不上）。

SDN：控制平面和数据平面分离；控制器算路由，南向接口下发流表，北向接口向应用开放。

# 二、帮 IP 干活的协议
记住==每个协议封装在谁里面、干什么==。
| 协议 | 要点 |
| ARP | IP→MAC，同网段；请求==广播==，响应单播；跨网段解析网关 |
| DHCP | UDP；Discover、Offer、Request、ACK；Discover 和 Request 广播 |
| ICMP | IP 承载；差错报告 + 询问；ping、traceroute（TTL 依次 1,2,…） |
| NAT | 既看 IP 也看端口，路由器工作到传输层 |
| IPv6 | 128 位，首部固定 40B，==路由器不分片==，无校验和，无广播 |
| 组播 | D 类只能做目的，低 23 位映射 MAC，IGMP 只在本地 |
| 移动 IP | 归属代理截获，隧道到外部代理；回程可以直接发 |

**跨网段发一次**：H1 用掩码判断不同网段 → ARP 查网关 MAC → 帧目的 MAC = 网关，IP 目的 = H2 → 网关转发，下一段再 ARP。

**DHCP 为什么 Request 还广播**：可能好几个服务器都提供了，要让其他服务器知道可以收回。Discover 源 0.0.0.0，目的 255.255.255.255。

**ICMP 差错**：目的不可达、时间超过、参数问题、重定向、源点抑制。对 ICMP 差错报文、非第一片、组播、特殊地址不发差错报告，以免越报越多。

**IPv6 压缩**：`2001:0DB8:0000:0000:0000:0000:0000:0001` → `2001:DB8::1`。前导 0 可省；`::` 只能用一次，否则还原不回去。

**组播映射**：只映射低 23 位，所以 32 个 IP 对一个 MAC。

路由器：路由选择 + 转发（输入端口、交换结构、输出端口），到第 3 层，隔离广播域，所以==能抑制广播风暴的只有路由器==。

# 三、路由
距离向量是问邻居，链路状态是所有人广播后各自看地图。图算法第 10 话学过，这里只是搬到分布式上。
:::def 距离向量更新：从 X 收到 ⟨N, d⟩，先算 d+1
表里没有 N：加入。下一跳就是 X：==一律用新值，即使变大==。下一跳不是 X：更小才换。
:::

s.text(270,28,'距离向量：',12);s.text(270,46,'只和邻居换整张表',11.5);s.text(270,64,'坏消息传得慢',11.5,'r')
:::
| 比较 | 距离向量 | 链路状态 |
| 交换内容 | 整张路由表 | 只有自己的邻接链路 |
| 发给谁 | 只发邻居 | 洪泛给所有路由器 |
| 知道多少 | 方向和距离 | 全局拓扑 |
| 收敛 | 慢 | 快 |

互联网太大，分成自治系统 AS：内部追求最短，AS 之间追求可达并符合商业策略。
| 协议 | 封装 | 算法 | 范围 |
| RIP | UDP 520 | 距离向量（跳数，最大 15，16 不可达） | AS 内 |
| OSPF | IP（89） | 链路状态 Dijkstra，分区域 | AS 内 |
| BGP | TCP 179 | 路径向量，不求最优 | AS 间 |

**为什么封装不同**：RIP 定期全发，丢了下次再说，UDP；OSPF 自己有确认，直接 IP；BGP 要可靠地交换大量信息又只发增量，TCP。这样讲我一下就记住了，比背表好。

**慢收敛**：距离向量只说多远不说路径，R3 不知道 R2 的路就是经过自己的，两边来回加到 16。BGP 列出经过的 AS，看到自己就知道有环，所以不会计数到无穷。

RIP 30 秒发一次，180 秒收不到算邻居不在。OSPF 分区域是为了把洪泛限制在区域内，主干区域 0。

# 四、传输层入门：UDP 与 TCP 首部
网络层是主机到主机，传输层是==进程到进程==。靠端口复用、分用；套接字 = IP + 端口。

端口：20/21 FTP、23 Telnet、25 SMTP、53 DNS、69 TFTP、80 HTTP、110 POP3、143 IMAP、161 SNMP、443 HTTPS。

TCP 四元组标识连接；UDP 按目的端口分用。

UDP 首部 8B，无连接，面向报文（不拆不合），无拥塞控制。
:::eg 校验和：`0x8000` + `0x8001`
相加 `0x1 0001`，进位加回 `0x0002`，取反 `0xFFFD`。接收方全部反码相加，全 1 才对。前面临时加 12B 伪首部（源 IP、目的 IP、协议号、长度），不发送，用来发现送错地方。只能发现错，==不保证可靠==。
:::

TCP：面向连接、可靠、全双工、点对点，字节流。最小首部 20B，首部长以 4B 为单位。

seq：本段第一字节。ack：==期望下一字节==，累积确认。SYN、FIN 占序号，纯 ACK 不占。MSS 只算数据部分，握手时协商。
:::eg 三种序号算法
连续：seq=100 带 200B，下一段 300，乙回 ack=300。
中间丢：发 100、300、500，第二段丢，乙一直回 300。
双向：我的 seq = 对方的 ack；我的 ack = 对方 seq + 对方数据长度。
:::

# 五、握手与挥手
:::sk 410 186 | 握手三次，挥手四次。TIME-WAIT 等 2MSL 只有主动关闭方有
s.line(30,10,30,178,'k',1.2);s.line(170,10,170,178,'k',1.2);s.text(24,8,'甲',11);s.text(164,8,'乙',11)
for y,t,c,d in ((20,'SYN seq=x','b',1),(44,'SYN+ACK seq=y ack=x+1','b',-1),(68,'ACK ack=y+1','b',1)):
    a,b=(30,170) if d>0 else (170,30);s.arrow(a,y,b,y+12,c,1);s.text(100,y+2,t,9.5,c,'middle',rot=0)
for y,t,c,d in ((100,'FIN','r',1),(120,'ACK','r',-1),(140,'FIN','r',-1),(160,'ACK','r',1)):
    a,b=(30,170) if d>0 else (170,30);s.arrow(a,y,b,y+10,c,1);s.text(100,y+2,t,9.5,c,'middle',rot=0)
s.text(8,176,'等2MSL',9.5,'r')
s.text(196,30,'为什么三次：',11.5);s.text(196,46,'防旧 SYN 造成错误',11.5)
s.text(196,70,'建连 1 RTT 后可发数据',11.5);s.text(196,86,'对方 1.5 RTT',11.5)
s.text(196,120,'释放（最快）：',11.5);s.text(196,136,'对方 1.5 RTT',11.5);s.text(196,152,'发起方 1 RTT+2MSL',11.5,'r')
:::
- 第三次可以带数据；SYN 不带数据但消耗一个序号。服务器第二次握手后分配资源，SYN 洪泛就钻这个空子。
- 初始序号不从 0 开始，防止和旧连接混淆。
- 全双工要分别关，所以有半关闭：我不发了，对方还能发。中间的 ACK 和 FIN 可以合并，那就是三次。
- TIME-WAIT 两个理由：保证最后的 ACK 到达（丢了对方重发 FIN）；让旧报文消失。

# 六、TCP 可靠与流量控制
和链路层同一个滑动窗口，但 RTT 变化大，还可能乱序。
:::def RTT 估计
$RTT_s=\frac78RTT_s+\frac18$新样本；$RTT_d=\frac34RTT_d+\frac14\vert RTT_s-$新样本$\vert$；$RTO=RTT_s+4RTT_d$。
:::
代入：$RTT_s=100$，$RTT_d=20$，新样本 140。$RTT_s=105$，$RTT_d=15+8.75=23.75$，$RTO=105+95=200$ms。==$RTT_d$ 用的是更新后的 105。==重传段的 RTT 不用（Karn），分不清确认对应哪一次。

快速重传：连收 3 个==重复== ACK（一共 4 个相同的 ACK），立即重传。

流量控制：接收方通过窗口字段告诉发送方还能装多少。
零窗口：窗口更新报文丢了会互相等死，所以发送方开持续计时器，定时发 1 字节探测。

糊涂窗口：首部 40B 带 1B 太亏。接收方攒够才通告；发送方用 Nagle，小数据攒到收到确认再发。

# 七、拥塞控制
发送窗口 = min(rwnd, cwnd)；可发 = 窗口 − 在途。例：rwnd=6000，cwnd=4000，在途 3000，还能发 1000。

没人告诉发送方网络情况，只能猜：丢包就当拥塞。

:::
:::def 四步
慢开始：每 RTT 翻倍，==不超过 ssthresh==。拥塞避免：每 RTT +1。
超时：ssthresh=cwnd/2，cwnd=1，==立即完成不占 RTT==。
3 重复 ACK：ssthresh=cwnd/2，cwnd=ssthresh，线性。
:::
为什么两种待遇：超时说明什么都收不到了，堵得厉害；3 冗余说明后面的段还能到，只是个别丢包。

单位统一成段再走流程。吞吐 = W ÷ RTT：64KB ÷ 100ms = 640KB/s。
:::note
和链路层的滑动窗口形状相同。差别：链路层按帧，TCP 按字节；链路层一条确定的线路，TCP 多一个 cwnd 猜网络。
:::

# 八、应用层
C/S：服务器长期在线，客户之间不直接通信。P2P：结点既是客户也是服务器，上传能力随结点增长。
| 协议 | 要点 |
| DNS | UDP 53（报文小，也可 TCP）；主机→本地递归，本地→其他迭代；缓存 |
| FTP | 两条 TCP：控制 21 全程，数据一次一条；主动 20，被动随便 |
| SMTP | TCP 25，推，7 位 ASCII，MIME 编码 |
| POP3 | TCP 110，拉，无状态 |
| IMAP | TCP 143，在服务器操作，有状态 |
| HTTP | TCP 80，无状态，Cookie |
