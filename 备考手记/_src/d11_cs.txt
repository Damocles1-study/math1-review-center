# 一、为什么要两种模式
银行柜台：程序是储户，OS 是柜员。储户进不了金库，要办事就按铃。
:::def 内核态与用户态
内核态：所有指令都能执行。用户态：只能非特权指令。
特权：开关中断、I/O、改 PSW、改基址/界限、设时钟、加载页表基址。
==用户→内核只有一条路：中断或异常（含 trap）==。内核→用户：改 PSW（iret）。
:::
用户态能：访存、算术、读时钟、trap（用户态才用得上）。

# 二、中断 vs 异常
:::sk 400 128 | 按来源分。回到哪是最常考的：故障回本条（缺页没做成要重做），陷阱回下一条（已经做完了）
s.box(120,6,120,24);s.text(180,23,'打断当前程序的事件',11.5,'k','middle',rot=0)
s.arrow(150,30,70,50);s.arrow(210,30,280,50)
s.box(14,50,110,26,'b');s.text(69,68,'外中断（异步）',11.5,'b','middle',rot=0)
s.box(226,50,110,26,'r');s.text(281,68,'内部异常（同步）',11.5,'r','middle',rot=0)
s.text(14,96,'I/O 完成、时钟',11.5);s.text(14,114,'回下一条',12,'b')
for i,(a,b) in enumerate((('故障 缺页','回本条'),('陷阱 trap','回下一条'),('终止 致命','不回'))):
    x=162+i*80;s.line(281,76,x+24,88,'r',.8);s.text(x,104,a,11);s.text(x,120,b,11.5,'r')
:::
外中断只在指令结束后响应；异常是指令执行中当场处理。
**缺页是异常（故障），不是中断。**

# 三、硬件做什么，OS 做什么
:::sk 400 150 | 这条分界线最关键。一开始硬件三件事，后面都是软件
s.line(14,20,14,136,'k',1)
A=['① 关中断','② 存断点 PC、PSW','③ 取入口（中断向量）'];B=['④ 存通用寄存器','⑤ 设屏蔽字','⑥ 开中断','⑦ 处理','⑧ 关中断','⑨ 恢复','⑩ 开中断','⑪ iret']
for i,t in enumerate(A): s.text(24,28+i*20,t,12.5,'r',rot=0)
s.box(180,12,8,62,'r',1);s.text(196,48,'硬件（中断隐指令）',12.5,'r')
for i,t in enumerate(B[:4]): s.text(24,90+i*14,t,11,'b',rot=0)
for i,t in enumerate(B[4:]): s.text(130,90+i*14,t,11,'b',rot=0)
s.text(240,120,'OS（服务程序）',12.5,'b')
:::
**为什么硬件先关中断**：断点还没存好又来一个就乱了。**为什么 PC、PSW 由硬件存**：服务程序一开始 PC 就变了。

中断 vs 子程序：子程序只存 PC；中断还要存 PSW 并切内核态。
时钟中断服务程序：更新系统时间、当前进程已用时间、减时间片，用完就调度。

# 四、系统调用
程序接口。传参（寄存器）→ trap → 内核执行服务例程 → 返回。
**发起在用户态，执行在内核态。**缺页发生在用户态、处理在内核态。==进程切换连「发生」都只能在内核态==。
`printf` 是库函数（内部 write）；`sin()` 不进内核；Shell 是用户程序。

# 五、OS 骨架
接口：命令接口（人）、程序接口（程序）。
四特征：**并发、共享**（互为前提）、虚拟（时分、空分）、异步。并发 ≠ 并行，多任务不一定要多 CPU。

发展：单道批处理 → 多道（CPU、设备利用率高，吞吐大，开销变大，无交互）→ 分时（交互）→ 实时（讲截止）。

| 结构 | 特点 |
| 宏内核 | 快，模块耦合 |
| 微内核 | 可靠，服务在用户态，切换多；基本功能：进程、低级内存、中断、通信 |
| 外核 | 管分配 |

引导：ROM→BIOS 自检→MBR（磁盘第一个扇区，引导代码 + 分区表）→活动分区引导→加载 OS 到 RAM。
虚拟机：第一类裸金属（Hypervisor 直接跑硬件）；第二类寄居（跑在宿主 OS 上）。虚拟内核态实为用户态。

# 六、进程
菜谱和做菜：程序静态，进程动态。**进程 = PCB + 程序段 + 数据段**，PCB 是唯一标志。

:::sk 400 156 | 五态图。判断：进程还能不能接着算？能算只是轮不到就回就绪；算不下去就阻塞

    c='r' if k=='运行' else 'k';s.circle(x,y,24,c,1.1,ry=15);s.text(x,y+4,k,12,c,'middle',rot=0)

:::
- 不能：阻塞 → 运行、就绪 → 阻塞。
- 原语：创建、撤销、阻塞、唤醒（内核态，不可中断）。
- 创建：申请 PID、PCB → 分配资源 → 初始化 → 入就绪队列。登录、调度、服务、fork。
- 设备分配不会创建进程。

# 七、线程
| | 进程 | 线程 |
| 单位 | 资源分配 | CPU 调度 |
| 共享 | | 代码、数据、堆、打开的文件 |
| 私有 | | PC、寄存器、==栈==、TCB |

同进程切换线程不切页表。
| 类型 | OS 知道？ | 阻塞 |
| 用户级 | 不知道（内核只见进程） | 一个阻塞全阻塞 |
| 内核级 | 知道 | 只阻塞自己 |

模型：多对一（不能并行）、一对一（Linux）、多对多。

# 八、进程通信
| 方式 | 要点 |
| 共享内存 | ==最快==，自己用 PV |
| 消息传递 | send/receive，内核复制，可经信箱 |
| 管道 | 半双工，固定缓冲，满写阻塞空读阻塞 |
| 信号 | 异步通知，只传编号，返回用户态时处理 |
